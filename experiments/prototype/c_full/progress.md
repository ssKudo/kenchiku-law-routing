# (c) 本格版・範囲C 進捗記録

開始: 2026-11-12。設計書: ../DESIGN_c_full.md（範囲C＝法規全問、順位は 1 ホップ距離順と 2 TF-IDF類似度順の両方）。

## 設計判断（実施前に固定した点）

- 対象: 一級建築士 学科Ⅲ（法規）2017–2026 年・各30問 = 300問を目標。
  公式正答は Drive 索引に 9 年分（2020年除く）= 270問分あり。2020年は
  過去問ドットコム解説から正解を導出し、9年分で導出法の正答一致率を検証してから使う。
- 2026年 学科Ⅲ No.29 は全員得点 → 「特殊扱い」として分離集計（到達率の分母に入れない）。
- 種（入口）: 正解を知らずに決める方法として、法アプリ v1.4 の TF-IDF エンジン
  （char 2/3-gram TF-IDF＋TERMS辞書＋SYN展開＋見出しブースト＋長さ正規化）を
  Python に忠実移植し、問題文（題幹＋全選択肢）に対する上位3条を種とする。
  上位1条が正答条と一致するか（ルーティング精度）も併せて記録する。
- 文脈展開: v0.3 の規則を任意の種に一般化。種自身（ホップ0）→ 逆引き受け手
  （ホップ1。種の委任先法令の本文に種条文への参照＋「〜で定める」を含む条）
  → 引用先（ホップ2）→ 引用元（ホップ3、先頭40件キャップ＝v0.3 と同じ並び順）。
  逆引きの参照照合は法・令・規則については略称形（法第/令第/施行令第/規則第/
  施行規則第）＋正式名、その他法令は正式名のみに一般化した。
- 順位: (1) ホップ距離順（同ホップ内は法令ID・条番号順で決定化）、
  (2) TF-IDF 類似度順（v1.4 スコア降順、同点は法令ID・条番号順）。
- 判定: 厳密読み（正答条そのもの）／家族読み（同一法令・同一基幹番号＝枝番条を含む）。
- 正答条の主値: 正答肢の解説が引く条文を主とする。全肢分も併記。
  四肢で根拠条文が割れる「組合せ」型・「いくつあるか」型も、正答肢の条文を主とする
  （設計書に明文の定義が無いため、この扱いをここに明記）。

- TF-IDF 移植の検証（ステージ3準備）: 法アプリの実 JS を jsdom で動かし、
  テストクエリ3件で Python 移植とスコア・順位が完全一致することを確認した
  （確認申請→令2条の2 53.8、定期報告→附則48条の2 157.0、容積率→令135条の18 92.7。
  ドキュメント数も 2,726 で一致）。裸の用語クエリでは法6条は1位にならないのが
  アプリ本体の実際の挙動であり、v1.4 検証時の「法6条 #1」は問題文全文を
  貼った場合の結果とみられる。本測定は問題文全文を使うので問題なし。

## 記録（随時追記）

- 実装上の発見（ステージ3準備中）: v0.3 の build_subgraph.py は種条文のノード集合を
  `source LIKE '{article_id}%'` で取っており、法6条なら 60〜69条のノードまで
  前方一致で混ざる余地がある。本測定では条境界を正確に取る
  （`source = article_id OR source LIKE article_id || '\_%'`）に改め、
  「v0.3 の規則（種＋逆引き＋引用先＋引用元40件）の意味はそのまま、
  ノード集合の取り方だけ正確化した」ことを最終報告に明記する。
