# 非AI古典手法5チャンネル測定レポート（2026-11-14）

## 測った仕組み

- 土俵は fifty_measurement と同一： 2017–2026 の学科IIIから50問、各問プール30条文（延べ463条文）、材料は原文のみ（問題文も条文も原文）。
- baseline（言葉数え TF-IDF）は measure50 のスコア式を複製して再計算し、公表値（top-3 29/50・平均順位3.88）と **42問全問の順位が一致**することを確認してから使用した。
- 各チャンネルは「単独の順位付け」と「TF-IDF との合わせ技（RRF、k=60、順位合体）」の2通りで測定。
- 順位の付け方（同点時はプール順）は baseline と同一作法。正解条文がプール外の8問は全条件共通で対象外（top-3 は分母50、平均順位はプール内42問の平均）。
- 辞書とルールは、正解条文・50問の内容を見ずに、条文側の知識と建築法規の一般知識だけで作って測定前に凍結した（材料ファイルに構築方針を明記）。

## 結果（top-3 / 平均順位）

| チャンネル | 単独 | 合わせ技（RRF） |
|---|---|---|
| 言葉数え（baseline） | **29 / 3.88** | — |
| 1. ルールベース | 14 / 7.79 | 23 / 4.88 |
| 2. シソーラス正規化 | 29 / 3.93 | 29 / 3.90 |
| 3. 数値 | 18 / 6.45 | 27 / 4.26 |
| 4. 編集距離 | 29 / 3.81 | 29 / 3.83 |
| 5a. MinHash | 18 / 8.64 | 25 / 4.86 |
| 5b. SimHash | 17 / 10.55 | 22 / 5.69 |

**結論： 5チャンネルとも、単独でも合わせ技でも、素の言葉数えを超えられなかった。** 合わせ技は全チャンネルで baseline 未満 — 実力差のある相手との RRF は、強い側（言葉数え）の独走を平均化して沈める、というベクトル測定と同じ型の負け方をした。

## チャンネル別の所見

### 1. ルールベース（Aho-Corasick＋条件テーブル）
- 実装： pyahocorasick 2.3.1 でトリガー語を一括検出。条件テーブルは用途・構造・階数・行為・手続・設備・領域の42特徴（`materials/rules.json`）。発火した特徴ごとに、条文の見出し＋本文に加点キーワードがあれば +1.0、紐づく法令なら +0.5。
- カバレッジ： ルールが1つ以上発火した問題 48/50、1問平均3.7特徴、正解条文に加点が届いたのはプール内 36/42問。
- 単独では top-3 14 に留まる一方、baseline が圏外だった問題を2問拾った（2021-1： 4位→2位、2025-23： 7位→2位）。逆に baseline 1位の問題を24位・21位まで落とす例もあり（2017-26、2023-19）、粗い加点が精密な言葉数えの信号を上書きしてしまう。
- 解釈： ルールは「大枠の当たり」は持っているが、順位付けの物差しとしては粗すぎる。捨てる／絞るための一次フィルターや、加点ではなく足切り条件として使う形が本来の居場所と見える。

### 2. シソーラス正規化（辞書＋漢数字変換）
- 実装： 辞書は法令集アプリの TERMS/SYN（エンジン内蔵12対）を種に、一般語・言い換え→条文用語の対を約60対まで拡張（`materials/thesaurus.json`）。これに「質問文の算用数字→漢数字」変換（第○条と小数は除く）を加え、質問文を書き換えてから TF-IDF で測定。
- 結果： 50問中45問で質問文が実際に書き換わったのに、**正解条文の順位が動いたのは42問中わずか2問、しかも両方とも1つ悪化**（2020-3： 7→8、2021-20： 6→7）。top-3 は不動、平均は微悪化（3.88→3.93）。
- 解釈： 質問タグ実験で見えた「三十日前↔30日前」の橋渡し効果は、タグ側に両方の表記を**追加**したから効いたのであって、質問側の表記を**置換**すると、条文側に残っている算用数字表記（表や新しい条文）との一致まで消してしまう。橋は「足す」ものであって「入れ替える」ものではない、というのが今回の教訓。

### 3. 数値チャンネル
- 実装： 質問文と各条文から（数値，単位）ペアを抽出・正規化（漢数字・全角・単位換算： ㎡/m/日/分/階/人など）。質問の数値が条文側の同単位の数値と完全一致 +3、×1.5以内 +1、上下に挟まれる（跨ぎ） +1.5 でスコア化。
- カバレッジ： 数値を含む問題 36/50。正解条文にスコアが付いたのはプール内 15/42問だけ — 条文側は数値だらけで「同単位の数値がどこかにある」ことが珍しくなく、識別力になりにくい。
- 単独 top-3 18（うち単独1位が7問）と信号自体はあるが、baseline 1〜2位の問題を13〜17位まで落とす例が目立つ（2018-5、2024-6、2026-7）。合わせ技でも baseline の top-3 から2問落ちた。
- 解釈： 数値は「その条文の数字と合うか」ではなく「その数字で適用範囲が切り替わるか」を見ないと効かない。今の単純な一致・近傍・跨ぎでは、閾値の意味を取り切れていない。

### 4. 編集距離（表記ゆれ吸収）
- 実装： 質問側の内容語（漢字・カタカナの2文字以上の連なり）のうち条文に字面で無いものについて、rapidfuzz の編集距離が小さい条文側の語（同頭文字・距離1〜2）があれば、TF-IDF スコアに弱い加点（語の重みの半分、上位3語まで）。
- 結果： 弱い一致は延べ1,896件発生したが、**正解条文の順位が動いたのは2問だけ**（2022-18： 24→20 の改善、2021-20： 6→7 の悪化）。top-3 不動、平均は微改善（3.88→3.81）だが、実質は「ほぼ何も起きていない」。
- 解釈： 表記ゆれは、この試験問題と条文の間では主要な敗因ではない（問題文はもともと条文用語で書かれている）。加点が正解・競合の両方に等しくばら撒かれて相殺された面も大きい。

### 5. MinHash / SimHash
- 実装： 文字3-gram集合から MinHash（128本、推定Jaccard）と SimHash（64bit、出現回数重み、ハミング距離）。numpy 自前実装。
- 結果： 単独 top-3 は MinHash 18 / SimHash 17。ただし MinHash は baseline 圏外の問題を3問拾った（2017-6： 20位→3位、2020-14： 6位→3位、2022-14： 6位→3位）、SimHash も1問（2020-14： 6位→1位）。裏返すと落とした問題の方がはるかに多い（MinHash の top-3 脱落14問）。
- 解釈： ハッシュ系は「文書全体の指紋の近さ」を見るため、長い条文同士の漠然とした似通いを拾い、決め手の語の一致を埋もれさせる。一次ふるい（全条文規模での候補出し）の道具であって、30件プールの順位付けの道具ではない、という当初の見立て通りの結果。

## 総括

- 5チャンネル全部を同じ土俵で測った結果、**素の言葉数え（top-3 29/50）を超えるものはなかった**。合わせ技（RRF）は今回も全滅で、「弱い相方を混ぜると平均化で負ける」が再確認された。
- ただしチャンネルごとに「拾える問題」は実在する： ルール2問、MinHash 3問、SimHash 1問は baseline が圏外だった問題を top-3 に入れた。信号がゼロなのではなく、**順位付けの主役を張れるほど強くない**、というのが正確な評価。
- 辞書と編集距離の「ほぼ無変化」は、敗因の所在を示すデータとして意味がある： この50問では、表記ゆれと言葉のズレは入口の主犯ではない（問題文が条文用語で書かれているため）。置換型の正規化は有害ですらあった。
- 留保： (1) ルールテーブルと辞書は初版の手作りで、育てれば変わりうる。(2) 数値チャンネルのスコア式は単純な一致・近傍・跨ぎのみで、閾値の意味論は入れていない。(3) 土俵は今回も「言葉数えが選んだ30件プール内」で、全条文からの直接引きは未測定。(4) この50問には消防法・省エネ法を正解とする問題が含まれていない。
