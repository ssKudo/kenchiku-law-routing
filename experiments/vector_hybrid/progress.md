# ベクトル検索＋合わせ技（RRF）測定

開始: 2026-11-14（クドウ承認の2段計画： 5問パイロット → 崩壊でなければ50問）

## 設計
- 読み手ではなく「探し手」の物差し比較： TF-IDF（参照値） / ベクトル / 合わせ技（RRF k=60）
- 埋め込みモデル: intfloat/multilingual-e5-small（118Mパラメータ、多言語・日本語対応）
  - 実行: onnxruntime + 公式ONNX int8量子化ビルド（model_qint8_avx512_vnni.onnx、当VMのCPUがAVX512-VNNI対応のため）
  - ※ 当初予定の sentence-transformers + torch は PyTorch 配布サーバのタイムアウトで導入不可だったため ONNX 直接実行に切替（プーリング=平均、L2正規化は自前実装で e5 の公式手順どおり）
  - 接頭辞: 問題側 "query: " / 条文側 "passage: "（e5 公式）
  - 長文方針（一律）: トークナイザで 480 tokens ごとに分割（重なり 48 tokens）、チャンク埋め込みを平均して1本化（各チャンク L2 正規化後に平均し再正規化）。問題文は短いので通常1チャンク。
- 材料条件（条文側）: (a) 原文のみ (b) 原文＋質問タグ (c) 原文＋看板v2 (d) 原文＋両方 (e) 原文＋描写看板（問題側のみ変換問題文、他条件は原文問題文）
- 土俵: パイロット=各問 baseline top-30 プール内順位（延べ123条文）。50問=同方式（プール外8問は rank=null、平均はプール内42問、top-3 は50問分母 — fifty_measurement と同一集計）
- TF-IDF 参照: 既存結果と照合のうえ、RRF 用に全順位リストをエンジンで再計算し、公表済み正解順位と一致を検証してから使う
