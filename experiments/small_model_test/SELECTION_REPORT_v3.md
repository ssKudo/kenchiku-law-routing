# 選択実験 v3 報告（番号をやめ、言葉そのものを書かせる）

日時: 2026-11-12
対象: v1/v2 と同じ5問（2017年 学科III No.21, 22, 24, 4 と対照 No.1）
モデル: Qwen2.5-1.5B-Instruct GGUF Q4_K_M（llama.cpp、temp 0.2、seed 42）
検索: (c) 本格版ステージ3と同一の TF-IDF エンジン
生データ: selection_results_v3.json（プロンプト文面・生出力・パース結果・秒数を含む）
実行スクリプト: selection_test_v3.py

## 結論（先行）

**言葉で書かせても、「内容で選べた」とは言えない。** 失敗の形が変わっただけだった。
v1/v2 の失敗は「連番の列挙」だったが、v3 の失敗は「**候補リストを先頭から
順に写す**」こと。5問中3問（No.21, 22, 対照 No.1）で、モデルはリストの語を
ほぼ並び通りに大量に出力し、採用した先頭8語はリストの先頭8語とほぼ同一だった。
問題ごとに違う語が出るのはリスト自体が違うからで、「読んで選んだ」証拠にはならない。

唯一の例外は No.4 で、リストの中・後半から順序不同で7語を選び、順位も
わずかに改善した（10位→9位、全語を足す oracle の10位を上回った）。
内容に追随した選択が皆無ではないが、5問中1問では「務まる」とは言えない。

また No.24 は、リストに無い「都市計画法」という語だけを書いて終わった（選択ゼロ）。
oracle では3位（命中）だった問で、機会を丸ごと失った。

## v2 からの変更点（問題・リスト・モデル・温度・seed は同一）

1. 候補リストを**番号なし・言葉だけ**で提示した。
2. 選んだ言葉を、リストの表記のままカンマ区切りで書かせた。番号例・数字の例示はなし。
3. 並び順は元の順のみ（シャッフルなし）。
4. max_tokens のみ 128→256 に変更（日本語8語が途中で切れるのを防ぐため。
   サンプリング条件は同一）。
5. 候補リストは作り直していない。baseline / oracle は v1 の値を再掲。

|---|---|---|---|---|---|

新規にトップ3へ入った問はゼロ。対照問（No.1）の悪化はなし。

## 生出力の実態（診断）

- No.21: リスト20語中17語を**リストの順序通り**に出力（飛ばしたのは
  「建築設備士」「免許」「登録」の3語のみ）。先頭8語との一致 7/8。
- No.22: リスト20語中19語を**完全にリストの順序通り**に出力（最後の
  「管理する建築士」のみ欠落）。採用8語はリスト先頭8語と完全一致。
- No.1（対照）: リスト17語中12語を順序通り出力。採用8語は先頭8語と完全一致。
- No.4: 出力7語はリストの2, 11〜16番目あたりから順序不同で選ばれており、
  いずれも選択肢の内容（構造計算適合性判定・確認済証・計画変更・表示）に対応する。
  先頭8語との一致は 3/8、共通接頭辞 0。**この1問だけ「写し」でない選択。**
- No.24: 出力は「都市計画法」の1語のみ。候補リストには無い語。

### 形式面の遵守
- 「リストに無い言葉は書くな」: 5問中4問はリスト外の語ゼロ。ただし No.24 は
  リスト外の語**だけ**を書いた。
- 「最大8個まで」: **守れなかった**。No.21 は17語、No.22 は19語、No.1 は12語を
  出力した（本実験では v1/v2 の規則に倣い先頭8語を採用し、truncated として記録）。
  番号形式では守れていた個数制限が、言葉形式では崩れた。

## 失敗の切り分け

- リストの質（oracle 上限 2/5）は v1/v2 から不変で、今回も天井になっていない問が
  あるのは事実（No.21, 22, 4 は全語を足してもトップ3未満）。
- ただし今回の主因はそれ以前の段階にある: 3問で選択が「先頭からの写し」に
  なっており、リストの中身の良し悪し以前に、選択という行為が成立していない。
  v1/v2 の「連番」と v3 の「写し」は、**提示された列をそのまま再生する**という
  同じ素の挙動の表れと見るのが妥当。
- No.4 の例外は、選択肢に候補語がそのまま多く現れる問だった。問題文中の語を
  拾うことはできても、問題文に無い橋語を判断で選ぶ段階には達していない、
  という読みが自然。

## 速度

モデル呼び出しは1問あたり 15.1〜42.3 秒（平均 約26.5 秒、5問合計 約133 秒）。
v1（約23.6 秒）・v2（約21.0 秒）と同水準。

## この結果の意味と、次にやるなら

- 「番号→言葉」に変えても壁は残った。1.5B は入力された列（番号でも言葉でも）を
  再生する方向に倒れやすく、判断で抜き出す使い方は依然として成立していない。
- v2 報告で挙げた残りの候補（いずれも未実施）:
  1. **few-shot** — 「問題文 → 選ぶべき言葉」の実例を先に渡す。列の再生ではなく
     判断の型を見せる方法で、生成・選択の両形式に効く可能性がある本命。
  2. **3Bモデルとの比較** — 同じ5問・同じ v3 プロンプトで Qwen2.5-3B に書かせ、
     壁がモデルの大きさの問題か形式の問題かを分ける。
  3. **リストの作り直し（盲検のまま）** — oracle 2/5 の天井問題は別途残る。
- なお対照問（No.1）は3条件とも1位を維持。語を足すこと自体の破壊力は小さい。
