# アキネーター式パイロット報告

## 結論（先に）

**アキネーター式は、一撃分類より前進しなかった。ただし敗因は方式ではなく回答役である。**

- 方式の天井は満点だった：モデル回答の代わりに「正答条自身のタグ」を答えとして使う oracle 条件では、**5問すべてで正答条が1位**になった。属性質問×タグという下ごしらえの設計には、正答条を先頭まで持ち上げるだけの弁別力がある。
- しかし Qwen2.5-1.5B の実際の回答は **60回中60回すべて「×」**。全×回答の下では並び替えは「yes タグの少ない条文ほど上」という逆向きの信号になり、**全問で baseline より悪化**した（対照問は1位→23位）。
- 問いを v5 の抽象的な「役立つか」から「問題文にその内容の記述が出てくるか」という具体的な読み取りに変えても、全×崩壊は再発した。**崩壊は問いの抽象度のせいではない**、という切り分けが v5 と合わせて強まった。

## 順位結果（プール＝各問 baseline 上位30条の中での順位）

| 問 | 正答条 | baseline | アキネーター式（モデル回答） | oracle（天井） |
|---|---|---|---|---|
| 2017 No.21 | 建築士法3条 | 5位 | 16位 | **1位** |
| 2017 No.22 | 建築士法20条 | 7位 | 24位 | **1位** |
| 2017 No.24 | 都市計画法58条の2 | 5位 | 13位 | **1位** |
| 2017 No.4 | 施行規則3条の2 | 10位 | 25位 | **1位** |
| 2017 No.1（対照） | 施行令112条 | 1位 | 23位 | **1位** |

トップ3命中：baseline 1/5 → アキネーター式 0/5 → oracle 5/5。

## モデルの回答分布（要点）

- 5問×12属性＝60回の回答：**○ 0回 / × 60回**、判定不能 0回、形式崩れ 0回。
- 出力形式は今回も完璧だった（全て「×」の1記号のみ）。壊れているのは中身だけ、という v5 と同じ絵。
- 具体例：No.21（建築士法の問題、選択肢は建築士の資格・業務の話ばかり）でも「建築士など資格を持つ人の免許や業務の記述が出てくるか」に×が返った。テキストを照らして答えているとは言えない。
- 速度：60回で合計142.9秒（1回約2.4秒、プロンプトキャッシュ使用）。速さは問題ではない。

## 切り分け：方式の天井 vs 回答の質

- 正答条のタグは yes が 3〜7個／12（例：施行規則3条の2 は7個）。全×回答との一致数は自動的に「12 − yes数」になり、**テーマのはっきりした（＝正答らしい）条文ほど一致数が低く沈む**。アキネーター式の順位が全問悪化した機械的な理由はこれ。
- oracle では、正答条とタグベクトルが完全一致する条文は各プールに1〜3条しかなく、正答条は TF-IDF の同点決着でも全問1位を取った。属性セット（12個）とキーワード・タグ付けの弁別力は、この5問では足りていた。
- つまり律速は100%回答側。アキネーター式は「答える者がまともなら強い」方式であり、今回の構成（素の1.5B・ゼロショット・このプロンプト形式）では回答役が不在だった、というのが正確な評価。

## 絞り込みの診断

- 一致数の分布（モデル回答）：しきい値 ≥11 で残るのは各問1〜7条、≥10 で9〜17条と、数字の上では絞り込みは「効いて」見えるが、残るのはタグの薄い条文群であり、正答条は含まれない（正答条の一致数はプール最大より2〜7点低い）。
- ハード消去（食い違う条文を属性の固定順に除外）：正答条は第1問目（procedure）〜第4問目（use）で消えた。**最初に yes タグが付いた属性のところで必ず死ぬ**——全×回答とハード消去の相性は最悪で、柔らかい並び替えにした判断自体は正しかったことが裏側からも分かる。

## 方法と留保

- 属性質問12個（手続き／構造／防火／用途／規模／人・資格／設備／敷地・道路・区域／検査・報告／契約・書面／定義／罰則・処分）は固定セット。governing を見ずに設計し、結果を見てからも直していない（attributes.json）。
- タグ付けは条文テキスト＋看板に対するキーワード規則の機械判定（tags.jsonl、根拠キーワード付き）。人手の精査はしていない。属性ごとの yes の出方には偏りがある（123条中：手続き54、防火45、人・資格48 に対し、検査・報告12、罰則・処分7、定義3）。弁別力の弱い属性が混ざっている可能性は残る。
- 測定はプール内（baseline 上位30条）の並び替えであり、全条文（約4,700条）検索への改善を測ったものではない。
- モデル条件は v1〜v5 と同一（Qwen2.5-1.5B-Instruct Q4_K_M、llama-server、temperature 0.2、seed 42）。回答の生出力は answers.json に全量保存。

## 次の課題（記録のみ。今回は実施しない）

1. 回答の全×偏りを崩せるか：few-shot で○の実例を先に見せる／「はい・いいえ」形式に変える／3Bモデルで比べる——のいずれかで、崩壊が「問いの形」由来か「モデルの大きさ」由来かをさらに切る。
2. 答える者を人間に替えた版（実務の法令調べ支援としての対話式絞り込み）は、oracle の結果が示す通り方式としては即成立する見込み。1.5B の回答役とは切り離して評価できる。
3. タグ側の改良：yes の出方が偏る属性（定義・検査・罰則）のタグ規則の見直し。ただし属性セットの変更は次の測定プロトコルとして新たに固定してから行う（結果を見て直すと測定が濁るため）。
