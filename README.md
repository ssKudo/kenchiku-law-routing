# kenchiku-law-routing

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24242198.svg)](https://doi.org/10.5281/zenodo.24242198)

**建築法規の入口ルーティング実験** ― 問題文から「根拠条文はどれか」に当たりをつける検索の前段（ルーティング）を、札束で殴らない軽い仕組みだけでどこまで正確にできるかを実測した研究記録です。

対象は一級建築士 学科Ⅲ（法規）の過去問と、建築基準法を中心とする11法令の条文群。読み手の大規模モデルに全文を読ませる方式（本研究では「札束で殴る」と呼ぶ）を使わず、

- **言葉数え（TF-IDF 系の語彙一致）** を背骨に、
- **事前の下ごしらえ**（条文への単語タグ・メタデータ・看板などの付加）を足し物に、
- **小型の採点モデル**（cross-encoder、0.1〜0.6B級）を最後のひと押しに、

という「ケチケチRAG」の構成で、端末（エッジ）で完結する法令検索の入口精度を測りました。中心的な知見は **「小型モデルの座席表」**：小型モデルには務まる席（低重みの最終押し・学習内の一信号）と、壊れる席（リストから選ばせる・全文を読ませる・単独で並べ替える）がある、という実測による切り分けです。

総括レポートは [`report/REPORT_2026-11-15_小型モデルの座席表.md`](report/REPORT_2026-11-15_小型モデルの座席表.md)（論文草稿の種）。

## 用語

本研究で使っている呼び名の説明です。

- **おなじみ**： その会社・その業務で繰り返し引かれる条文のこと。建築法規は約4,700条ありますが、確認申請・意匠・構造・建材の仕様確認など、業務によって実際に引かれる条文には強い偏りがあります。本実験では、一級建築士試験の過去問で「正解の根拠条文」として繰り返し登場した条文をおなじみとし、対象の問題を除いた残りの問題で2回以上正解になった条文を数えて使いました。先に当たりをつけるのは一見「出来レース」ですが、偏りが実在する以上、**その偏りを検索に反映させることこそ、むしろ推奨される設計だ**というのが本研究の立場です。検索理論では、利用の偏りを先取りする事前確率（Document Prior）に当たり、実務では出題頻度の代わりに、自社の調べものログやFAQの参照回数、担当業務ごとの頻出条文リストに差し替えられます（総括レポート第9節）。
- **フック**： 入口の検索で最初に当てる「扉」になる条文。フックだけを対象に検索し、そこから参照・委任のグラフをたどって候補を広げる方式を測りました。
- **看板**： 条文に付ける、その条文が何を定めているかを平たい言葉で書いた短い案内文。条文側の「下ごしらえ」の一種です。
- **質問タグ／単語タグ**： その条文がどんな問われ方をするかを先回りして付けた語句。条文側の下ごしらえの一種です。
- **下ごしらえ**： 検索の前に条文側へ施しておく加工（タグ・メタデータ・看板など）の総称。
- **入口ルーティング**： 質問文から根拠条文の候補を絞り込む、検索の前段の処理。本研究の主題です。
- **土俵**： 測定の条件・候補集合のこと（例： 過去問50問について、言葉数えの上位30件を候補とする測定）。
- **札束で殴る**： 大規模モデルに大量の条文を読ませて解く力技の方式を、本研究ではこう呼んでいます。対置される、軽い仕組みだけで組む方式を **ケチケチRAG** と呼びます。

## 主要結果

### 土俵A：50問プール（並べ替え）

一級建築士 学科Ⅲ 2017〜2026 から50問。言葉数えが選んだ上位30条文のプール内で、正解条文を上位3位に入れられるか（プール内に正解があるのは42問＝天井42）。

| 方式 | top-3 | 平均順位 |
|---|---|---|
| 言葉数え（原文のみ） | 29 | 3.88 |
| 連結スタック（原文＋単語タグ＋メタデータ） | 31 | 3.38 |
| スタック × ruri-v3（重み付き和 α=0.80〜0.90） | 33 | 3.26〜3.33 |
| スタック × bge cross-encoder（0.8/0.2） | 34 | 3.14 |
| **learning-to-rank（leave-one-year-out 検証）** | **34** | **2.88〜2.93** |
| （参考）cross-encoder 単独の並べ替え | 13 | 9.33 |
| （参考）ベクトル単独（multilingual-e5-small） | 17 | 8.74 |

### 土俵B：249問パイプライン（到達）

正解条文が証拠で確定した249問。入口で種を3条文選び、参照・委任グラフ（JLaw-CiteGraph）を辿って正解条文に届くか。

| 入口の条件 | strict | family |
|---|---|---|
| 通常の種（全2,726条文から言葉数え top-3） | 62.7% | 70.7% |
| フックA：グラフの結節点のみ（374条文） | 55.4% | 66.3% |
| **フックB：A ＋ おなじみ（繰り返し正解になった条文）** | **63.9%** | **72.3%** |

「フック」方式はグラフの形だけでは負け、「おなじみ」という下ごしらえを足して初めて参照を超えました。学習（learning-to-rank）の重みでも、単語タグと「おなじみ」が独立した正の重みを持ち、ベクトル類似度やフック印はほぼゼロでした。

## 再現方法の要点

- 言葉数えエンジンは `experiments/prototype/c_full/work/engine.py`（文字2/3グラム TF-IDF＋用語辞書）。各実験の測定スクリプトは、その実験フォルダの `work/` にあります。
- 条文データは e-Gov 法令検索の公開データ（法令本文は著作権法13条により著作権の対象外）から取得したものを使いました。本リポジトリには条文全文のデータベースは含めていません。
- 参照・委任グラフには **JLaw-CiteGraph**（yabooung、https://github.com/yabooung/jp-law-citation-graph 、データは CC BY 4.0）を使いました。本リポジトリにはそのデータベース自体は含めず、利用して作った派生データ（フック集合など）のみを置いています。
- 使ったモデル： Qwen2.5-1.5B-Instruct（GGUF Q4_K_M、llama.cpp で実行）、LFM3-1.7B（GGUF）、bge-reranker-v2-m3、hotchpotch/japanese-reranker-cross-encoder-small-v1、multilingual-e5-small、ruri-v3-30m。各モデルのライセンスは提供元のものに従います（本リポジトリにモデルファイルは含めていません）。

## データと著作権の注意

- **過去問の問題文・選択肢の全文は含めていません。** 一級建築士試験の問題は試験実施団体の著作物のため、本リポジトリでは問題を「実施年＋問題番号」で参照し、正解条文との対応表（`data/governing_map.jsonl`）だけを公開しています。再現実験には、公式の問題PDF等を各自で入手してください。
- 解説文など、第三者の著作物にあたるテキストも含めていません。
- 法令・告示の本文そのものは著作権法13条により著作権の対象ではありませんが、本リポジトリに含まれるのは条文から作った派生データ（タグ・看板・対応表など）です。
